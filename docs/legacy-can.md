# LEGACY CAN 发帧修复与验证

## 发帧规则

| 输入帧 | 条件 | 修改范围 |
| --- | --- | --- |
| `0x045` | DLC 8，自动档位，拨杆值 0～200 | 只读，更新速度档位，不发帧 |
| `0x2F8` | DLC 8，FSD 总开关开启，偏移 1～33 | 字节 5 低 6 位写入偏移 +30，保留两个单位位 |
| `0x438` | DLC 8，FSD 总开关开启，重写限速开启 | 字节 7 低 7 位写入 100，保留最高位 |
| `0x3EE mux-0` | DLC 8，FSD 开启，原车已选或强制激活 | bit 46、速度档位；字节 7 低 4 位按独立开关写入 |
| `0x3EE mux-1` | DLC 8，当前配置及当前驱动会话已有有效 mux-0 触发 | bit 19 清零；按视觉限速开关决定是否清除 bit 48 |

模式、FSD 开关、强制激活变化，以及驱动恢复，都会使旧触发状态失效。即使关闭再开启或模式切换发生在两帧之间，也必须重新收到有效 mux-0。

配置启用时持续应用所设偏移，不增加原车操作后的自动暂停。总开关从下一输入帧处理边界生效，已进入硬件的在途帧不承诺撤回。远光灯保持独立控制，但自适应灯关闭时清除手势并停止改写。

驱动只将标准 Classical CAN 数据帧交给处理器。扩展帧、远程帧、不合法 DLC 被跳过；后续合法帧仍会被读取。不新增滚动计数器、校验和或发帧频率规则。

## 配置与诊断

- `legacyOffset`：0～33，0 表示停用。偏移跟随原车用户偏移单位，不强制转换为 km/h。
- `legacyByte7Enable`：0/1，NVS 键 `dg`，默认开启。
- `legacyByte7Value`：0～15，NVS 键 `dh`，默认 15；加载越界存储值时限制到 15。
- 已识别的设置参数必须为非负十进制整数，布尔值只能是 0/1。保留原有 HW3 slew/encoding 的范围限制行为。任一参数错误，整个请求不改变 RAM 配置和 NVS。
- 状态接口和诊断包同时包含字节 7 配置及原车单位位；嗅探值在改写前采样。
- `modifiedCount` 沿用 mux-1 nag-only 成功不计数的约定；失败统一计入 `errorCount`。首次 FSD 修改时间仅在驱动成功入队后记录，不能作为车辆已接收或已执行的证明。

## 自动验证

```sh
python3 tests/run_legacy_checks.py
node --test tests/legacy_ui.test.mjs
pio run
```

原生测试使用 AddressSanitizer 和 UndefinedBehaviorSanitizer，覆盖 14 组 CAN/配置回归场景，包括并发切换、mux 顺序、恢复、各位掩码、失败计数和非法帧。API、NVS 与状态测试直接提取并编译固件实际函数，检查部分更新、历史键恢复、重启加载、合法 JSON 和 debug 附加字段容量。页面测试执行手机及车机实际回显片段，检查关闭值、零值及两个独立单位位。

`pio run` 编译 ESP32、ESP32-S3、两种 Wi-Fi 桥接变体及其 debug 环境，共八个环境。主机模拟和编译验证不能替代实车验证；车辆接收、仪表表现和与原车周期帧的竞争仍需总线采集或台架/实车确认。
